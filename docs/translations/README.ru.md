# Killing Floor Map Importer

[English](../../README.md) · **Русский** · [Español](./README.es.md) · [Português](./README.pt.md) · [Lietuvių](./README.lt.md) · [Polski](./README.pl.md) · [Français](./README.fr.md) · [中文](./README.zh.md) · [日本語](./README.ja.md)

Импортирует карты из других игр в **Killing Floor 1** как настоящие уровни `.rom` (Unreal Engine 2.5, версия файла 128 / licensee 29). Пакет пишется с нуля — без KFEd, без промежуточных форматов, без ручных шагов: указываешь на файл карты и получаешь `.rom`, который кладётся в `KillingFloor\Maps` и играется.

Исходный движок на сегодня — **GoldSrc BSP v30**: Counter-Strike 1.6, Half-Life и их моды. Чтение исходной игры — один модуль (`src/goldsrc/`) перед общим конвейером сборки и записи, и добавление других игр — запланированный путь развития, см. [Планы](#планы-другие-исходные-игры).

> Сторона Unreal разобрана вручную. Порядок сериализации `UModel` v128 и раскладка запечённых лайтмапов внутри него не описаны нигде, а публичного конвертера GoldSrc → Unreal не существует. Разбор — в [`docs/RESEARCH.md`](./RESEARCH.ru.md), все грабли, стоившие времени, — в [`docs/GOTCHAS.md`](../GOTCHAS.md).

## Состояние

| Возможность | Состояние |
| --- | --- |
| Геометрия, текстуры, коллизия, точки спавна | работает — проверено в живом клиенте |
| Небо — шесть настоящих картинок карты из `gfx/env` | работает |
| Вода — плавание, тонировка экрана, слоёные текстуры | работает |
| Спрайты (`.spr`) и модели (`.mdl`) | работает |
| Двери и разбиваемые стёкла | работает — `KFDoorMover` + `KFUseTrigger`, `KFGlassMover` |
| Запечённый свет | частично — люксели читаются и пакуются в атласы DXT3, но клиент рисует ровный зональный ambient (см. [Чего пока нет](#чего-пока-нет)) |
| Зоны / окклюзия по PVS, пути ботов, кнопки и триггеры | нет |

## Что нужно

- Установленная **Killing Floor 1** (или non-Steam SDK) — туда кладётся готовый `.rom`.
- Установленные **Counter-Strike 1.6 / Half-Life** — там лежат стоковые архивы текстур `.wad` и небо `gfx/env`. Скачанная карта обычно приходит одним `.bsp` и без них не обойдётся: иначе все текстуры выйдут пурпурными, а неба не будет вовсе.
- **Node.js ≥ 18** для CLI. Десктопному приложению ничего дополнительно не нужно.

Никакого игрового контента в репозитории нет, ни с той, ни с другой стороны. Инструмент указывает на твои собственные установки.

## Десктопное приложение (Windows / macOS / Linux)

Готовые самодостаточные сборки — на странице [Releases](https://github.com/TheBestPlan/killingfloor-map-importer/releases):

- **Windows** — `…-setup.exe` (установщик) или `…-portable.exe` (запуск без установки).
- **macOS** — `…-mac-x64.dmg` (Intel) или `…-mac-arm64.dmg` (Apple Silicon).
- **Linux** — `…-linux-x86_64.AppImage` (запуск где угодно) или `…-linux-amd64.deb`.

Перетащи `.bsp` в окно, выбери папку вывода и папку Counter-Strike, нажми Convert. Каждая карта конвертируется в дочернем процессе, поэтому падение или гигантская карта не утащат окно за собой. Сборки без подписи, поэтому при первом запуске ОС может предупредить (Windows SmartScreen → *Подробнее → Выполнить в любом случае*; macOS → правый клик → *Открыть*).

### Собрать самому

```bash
pnpm install
pnpm start          # запустить приложение из исходников
pnpm run dist       # собрать установщики для текущей ОС в dist/
```

## CLI

```bash
node src/cli.js "…/cstrike/maps/cs_assault.bsp" --out "…/KillingFloor/Maps" \
     --name KF-CS-Assault --cs-dir "…/Counter-Strike 1.6" --verify
```

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `--out <файл\|папка>` | рядом с `.bsp` | куда писать `.rom` |
| `--name KF-Xxx` | `KF-<имя bsp>` | имя карты внутри пакета |
| `--scale <n>` | `1.9165` | юниты GoldSrc → юниты Unreal |
| `--lightmap-scale <n>` | `32` | размер люкселя в юнитах Unreal |
| `--cs-dir <папка>` | — | папка клиента Counter-Strike 1.6: стоковые `.wad`, небо `gfx/env`, `sprites/*.spr` |
| `--wad <папка>` | папка карты и две над ней | дополнительные папки поиска `.wad` |
| `--geometry mesh\|bsp\|both` | `mesh` | чем рисуется мир: статикмешами, BSP, или BSP при мешах только под коллизию |
| `--verify` | выкл | перечитать готовый `.rom` независимым ридером и проверить инварианты |
| `--no-spawns` | выкл | не переносить точки спавна |
| `--ase` | выкл | дополнительно выдать `.ase` / `.t3d` (бекенд B, для доводки руками в KFEd) |

Диагностические ключи оставлены намеренно: `--no-sky`, `--no-extras`, `--no-light`, `--tree-translate`, `--spawn-index N`. Переменная `KF_SPAWN_AT="x,y,z[,yaw]"` заменяет все точки спавна одной в этой точке — так попадают туда, где интересно.

## Что переносится

| | Как |
| --- | --- |
| геометрия мира | статикмеши, один материал на меш, нарезка сеткой 2048 UU, обратная намотка (зеркало по Y переворачивает ориентацию треугольника); коллизия — их kDOP-дерево |
| brush-энтити (`func_wall`, `func_illusionary`, `func_ladder`…) | тем же путём, с учётом ключа `origin` энтити |
| двери (`func_door`, `func_door_rotating`) | `KFMod.KFDoorMover` + `KFMod.KFUseTrigger` — открываются клавишей действия и завариваются, как родные двери KF; `KeyPos`/`KeyRot` из `angle`/`lip`/`distance` |
| разбиваемые стёкла (`func_breakable`, material 0/7) | `KFMod.KFGlassMover`, `Health` из энтити, `Style = STY_Translucent` |
| вода (`func_water`) | полупрозрачная верхняя плоскость плюс `PhysicsVolume` с настоящим brush-боксом (`bWaterVolume`, туман, утопление) |
| спрайты (`env_sprite`, `env_glow`, `cycler_sprite`) | билборды `Engine.Effects`, additive или alpha по формату текстуры `.spr` |
| модели (`.mdl` на тех же энтити) | статикмеш в bind-позе плюс актор на каждый экземпляр; текстуры из модели или из `<имя>T.mdl` |
| текстуры | 8-битный miptex → `UTexture` P8 + `UPalette` **без перекодирования**; 4 мипа GoldSrc продолжаются точечной выборкой до 1×1 |
| маскированные текстуры (`{name`) | палитра переставляется, прозрачный индекс переезжает с 255 на 0, флаг `PF_Masked` |
| небо | шесть картинок `gfx/env/<skyname>*` → RGBA8 (без блочного сжатия — иначе полосы на градиентах) на кубе-скайбоксе; грани `sky` вырезаются из мешей; нет `skyname` — движковый дефолт `desert` |
| освещение | `ZoneInfo.AmbientBrightness` по теневому уровню собственных люкселей карты плюс акторы `Light`/`Sunlight` из светоэнтити; на BSP-маршруте ещё и атласы лайтмапов DXT3 внутри `UModel` |
| точки спавна | `info_player_start` / `info_player_deathmatch` → `PlayerStart`, поднятые на пол |
| масштаб | ×1.9165 по умолчанию (×2 — то, что намеряно на живых портах `KF-CS-*`, и при нём сетка люкселей GoldSrc в 16 юнитов ложится ровно на 32 UU в UE2.5) |

Не попадают в мир невидимые tool-текстуры — `aaatrigger`, `clip`, `null`, `hint`, — которым там и не место: 48 из 3206 на cs_assault, 25 из 5383 на de_dust2, 36 из 8528 на cs_italy.

## Чего пока нет

- **Запечённых теней.** Люксели GoldSrc сэмплируются и пишутся, но движок не применяет их в рантайме, поэтому освещение ровное — зональный ambient, выведенный из собственных люкселей карты. Вероятно, лечится проходом `Build Lighting` в KFEd.
- **Зон.** Всегда две (0 = солид, 1 = мир), окклюзии по PVS нет: рисуется всё. Для карт размера Counter-Strike это нормально.
- **Путей ботов.** `PathNode` / `ReachSpec` не генерируются — нужен проход `Build Paths` в KFEd.
- **Кнопок и поездов.** `func_button`, `trigger_*` и `func_train` остаются статичной геометрией.
- **Анимированные текстуры** переносятся первым кадром; `-0` (случайный тайлинг) — как обычная текстура.
- **Non-power-of-two текстуры** ресемплятся в ближайшую степень двойки (иначе UE2.5 считает размер буфера по `UBits` и портит кучу). Текстурные оси домножаются на `pot/orig`, так что UV не едут.

## Планы: другие исходные игры

Конвейер разделён так, что от исходной игры зависит только одна часть: `src/goldsrc/` читает карту, `src/build/` превращает её в структуры Unreal, `src/unreal/` пишет пакет. Добавить игру — значит написать новый ридер, выдающий ту же промежуточную форму (грани с UV, текстуры, энтити, сетка лайтмапа); в `src/unreal/` при этом не меняется ничего. Очевидные следующие кандидаты — варианты BSP из Quake, Quake II и Source: то же семейство форматов, тот же писатель `UModel` на выходе.

Вклад в эту сторону приветствуется; начинать — с [`docs/RESEARCH.md`](./RESEARCH.ru.md) про целевой формат и [`docs/GOTCHAS.md`](../GOTCHAS.md) про инварианты, которые ломать нельзя.

## Как это проверено

```bash
pnpm test          # node test/selfcheck.js
```

19 проверок, все зелёные. Несущие:

- сериализатор `UModel` v128 переписывает **41 стоковую карту Killing Floor байт в байт** (расхождения только в payload signalling-NaN, который JS нормализует);
- round-trip compact index и `FString`;
- на 25 картах Counter-Strike: расчётный объём лайтмапов укладывается в лампу `LIGHTING`, намотка граней `Newell == −normal`, вершины лежат на плоскости грани;
- каждый стоковый объект `UPolys` укладывается в раскладку точно (6054 объекта, 37136 полигонов, 0 расхождений);
- кодер DXT3, ридеры `.mdl` и `.spr`, ресемплер Ланцоша.

Игровые файлы ищутся в обычных местах Steam; без них эти проверки честно падают, а не проходят пустыми, поэтому `pnpm test` надо гонять на машине с играми (CI только смоук-тестит упаковку).

`--verify` перечитывает готовый `.rom` независимым ридером и проверяет 22 инварианта: заголовок, таблицы, диапазоны serial, разрешимость ссылок, единичность нормалей узлов, принадлежность вершин плоскости, намотку, соответствие секций полигонам узлов, диапазоны лайтмапов и попадание их UV в атлас, корректность DXT3, что дерево действительно дерево, и полную мип-цепочку у каждой текстуры. Измерено, всё чисто:

```
cs_assault  3206 граней -> 7247 треугольников в 323 мешах   149 текстур  13.41 MB
de_dust2    5383 грани  -> 9932 треугольника в 229 мешах     36 текстур  12.05 MB
cs_italy    8528 граней -> 21038 треугольников в 396 мешах   89 текстур  16.35 MB

cs_assault --geometry bsp   3158/3206 граней (98.5%)  3570 узлов  3569 лайтмапов  5 атласов  14.90 MB
```

`test/repack.js <карта.rom>` пересобирает существующую карту тем же писателем и сравнивает байты: на `KF-CS-Iceworld` расхождение — **один байт** (`packageFlags`). `test/render-test.ps1` запускает клиент прямо в карту в обход лобби и выносит вердикт по строкам `Critical:` в `KillingFloor.log`. `KF-CS-Assault` прогнан по всем 20 точкам спавна без единого `Critical`.

**Тестами не покрыто:** как карта выглядит в 3D-вьюпорте KFEd (там свой рендер-путь) и правильность самой картинки — тесты ловят падения, а не артефакты.

## Проверка карты в игре

[`harness/play.ps1`](../../harness/README.md) запускает клиент в карту, шлёт команды в консоль через `PostMessage`, снимает кадры движком и конвертирует их в PNG; `harness/flat.js` судит кадры по плотности краёв (18–30 % — норма, ~1.4 % — кадр, где мир не нарисовался). Главное правило: **отрицательный результат не считается, пока не проверен сам харнесс** на заведомо рабочем случае. Подробности и грабли — в [`harness/README.md`](../../harness/README.md) и [`docs/GOTCHAS.md`](../GOTCHAS.md) §7.

## Правовая рамка

Конвертация карты не даёт права её публиковать. Valve разрешает перенос ассетов между играми в некоммерческих модах, но просит **не портировать ванильные карты дословно**; Tripwire требует, чтобы моды не содержали чужой защищённой собственности без письменного разрешения и распространялись бесплатно. Оба публичных порта карт Counter-Strike в Killing Floor (`KF-Dust_1`, `KF-Assault`) удалены из Steam Workshop. Кастомные карты принадлежат их авторам, а не Valve — разрешение давать им.

Импортер не поставляет игрового контента и сам по себе ничего не производит: то, что он пишет, производно от карты, которую ты ему дал, и куда это можно нести — вопрос между тобой и владельцем исходной карты.
